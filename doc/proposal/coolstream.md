# Proposal: CoolStream for Interactive `ask` Sessions

**Author:** LANNOCC
**Date:** November 13, 2025
**Status:** Draft

## 1. Introduction & Motivation

The `ask` command is a cornerstone of the SideKick CLI, providing a direct interface to our AI models. However, its current request-response model introduces a noticeable latency. The user issues a prompt and then waits, sometimes for a considerable period, for the entire response to be generated and displayed. This creates a disjointed, "stop-and-wait" user experience.

Furthermore, the powerful `--work` option, which applies code changes directly to the local filesystem, operates as a post-processing step on the complete AI response. While functional, this lacks the dynamic feel of an AI actively "working" on the user's behalf.

This proposal, codenamed **CoolStream**, outlines a plan to revolutionize the `ask` command by implementing real-time, token-by-token streaming output. More than just a simple stream, this new implementation will integrate deeply with the `--work` mode to create a visually engaging and highly responsive interactive session, where code blocks are applied and then gracefully collapsed in the terminal as they are received.

## 2. Core Requirements

1.  **Real-Time Streaming:** The `ask` command's output should be streamed to the standard output as it is generated by the AI, eliminating the "waiting for reply" dead time.
2.  **Dynamic Code Block Handling:** When used with the `--work` flag, the streaming output must have special behavior for code blocks:
    *   The content of a code block should be printed to the terminal as it streams in.
    *   Upon completion of the code block (i.e., when the closing ``` is received), the file-writing or patching logic from `sk/worker.py` must be immediately triggered for that block.
    *   After the file operation is complete, the code block that was just printed to the terminal should be removed or "collapsed", and replaced with a summary line (e.g., `-> WROTE: path/to/file.py`).
3.  **Preservation of Functionality:** All existing features of `ask`, including transcript generation (`-w`), must remain fully functional. The final transcript file should contain the complete, unmodified AI response.

## 3. Proposed Implementation

The implementation will involve modifications to the AI client layer and the main `ask` command logic. The core of the dynamic display will be achieved using ANSI escape codes for cursor manipulation.

### 3.1. AI Client Layer (`sk/ai/`)

Both `sk/ai/google.py` and `sk/ai/openai.py` will be updated. The primary `prompt_*` functions currently return a complete string. New streaming-capable versions will be created.

-   **New Streaming Functions:** We will introduce new functions like `stream_prompt_for_text` and `stream_prompt_with_file_for_text`.
-   **Yielding Tokens:** Instead of awaiting the full response, these functions will use the streaming capabilities of the underlying `genai` and `openai` libraries. They will become generator functions that `yield` chunks of text (tokens) as they are received from the API.

### 3.2. Command Layer (`sk/cmd.py`)

The `ask_question` function will be significantly refactored to handle the stream and manage the UI.

-   **State Management:** A simple state machine will be implemented within the streaming loop to track whether the output is currently inside a code block. The states will be `NORMAL` and `IN_CODE_BLOCK`.

-   **Streaming and Buffering Loop:** The function will iterate over the tokens yielded by the new AI client functions. Inside the loop, it will:
    1.  Append the incoming token to a `full_answer` buffer (for the transcript).
    2.  Print the token directly to `stdout` for the user to see in real-time.
    3.  Detect the start (` ``` `) and end (` ``` `) of code blocks to transition between states.
    4.  If entering the `IN_CODE_BLOCK` state, it will start a new buffer for the code content and begin counting the number of lines being printed for this block.
    5.  If exiting the `IN_CODE_BLOCK` state, it will trigger the "cool work" logic.

-   **The "Cool Work" Logic:**
    1.  **Trigger:** When the closing ``` of a code block is processed.
    2.  **Worker Invocation:** A new, more granular function, `worker.do_work_on_block`, will be called. It will be passed the completed code block buffer and the `full_answer` buffer up to that point (to provide context for filename inference).
    3.  **UI Manipulation (ANSI Escape Codes):**
        -   After the worker function returns its result (e.g., "WROTE: file.py"), the code will execute a series of `print()` statements containing ANSI escape codes.
        -   `\x1b[<N>A`: Move cursor up `N` lines, where `N` is the number of lines the code block occupied.
        -   `\x1b[J`: Erase from cursor to the end of the screen.
        -   This effectively removes the just-streamed code block from the visible terminal history.
    4.  **Display Summary:** Immediately after clearing the block, the summary message from the worker is printed, leaving a clean, concise record of the action taken.

## 4. Challenges and Considerations

-   **Terminal Compatibility:** The use of ANSI escape codes is well-supported in modern terminals on Linux, macOS, and Windows (Windows Terminal, PowerShell Core). However, it may result in garbled output in older environments like the legacy Windows `cmd.exe`. This is an acceptable trade-off for the enhanced experience on modern platforms.
-   **Partial Token Matching:** The logic for detecting ``` markers must be robust enough to handle cases where the marker is split across multiple received tokens. A small buffer for the last few characters can easily solve this.
-   **Worker Context:** The `sk-worker`'s filename inference relies on the text preceding a code block. The proposed solution of passing the `full_answer` buffer up to the point of the code block's completion ensures this context is always available.

## 5. Conclusion

Implementing **CoolStream** will transform the `ask` command from a static tool into a dynamic and interactive assistant. The immediate feedback from streaming will dramatically improve perceived performance and user engagement. The innovative integration with `--work` mode will not only be visually impressive but will provide clear, real-time insight into the AI's actions, making SideKick an even more powerful and intuitive development partner.
