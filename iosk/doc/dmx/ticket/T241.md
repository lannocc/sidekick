# Ticket T241: Customization "switch" (calculation overrides)

- Status: **open**
- Workboard: **Diametrix**
- Column: **Functionality**

## Description

Given some notes from T235 and elsewhere, we might need to already build a "switch" between customizations.

An example, as mentioned in T235, might be bank A that calculates total income after taxes needs to as Adjusted gross income less Federal and State taxes, whereas bank B uses a different formula.

For example:

* The original `Diametrix- Consumer Loans.xlsx` uses Line 9 Total Income, less taxes.
* The updated `Diametrix- Consumer Loans- Alice Smith.xlsx` uses Line 11 Adjusted Gross Income, less taxes.

These could be 2 different bank scenarios.

## Comments

I think the solution is an optional calc() function to attach to any Field. These will be called inline from the current computer.py and let custom definitions override the default based on logged-in bank ID (T242).

Back-End Customization Plan
===========================

Implement a calculator "spread" applicator which reads calculation definitions and attaches these inline at the various points of the profile. A default spread() implementation on each profile layout type (Map, List) will simply iterate through all immediate children items in order and call their spread() function, which continues recursively and does no arithmetic by default.

Overrides to the default calculations would go in a "spread" definition file, which is a simple indented structure of profile item labels (corresponding to the locations in the profile data tree) and then python code for the actual calculations.


Example
-------

```
crop
    sales:
        return sales.sep + sales.nov

    year
        revenue:
            return year.acres * year.xyield * year.price
```

So items indent based on their location in the tree, and items ending in colon (":") indicate python (calculation) code to follow beneath them.

The Diametrix system (probably during startup) would load and pre-parse the default spreads and bank-customized spreads and apply them in order so that defaults get applied first and then customizations (if there are any) only override the points they reference.
