# Ticket T253: Field custom format options refactor

- Status: **open**
- Workboard: **Diametrix**
- Column: **(Backlog)**

## Description

As the first step of allowing custom format options on different Fields (for example, allowing >100% in Percent) we need to transition the Field class and all subclasses to not use staticmethod for their normalize/format scheme, or do it a different way. These were all designed with the staticmethod flag so that they could be called directly from elsewhere, but I don't think that has happened. By doing so, they have no "self" reference and thus no instance-parameters (options) would be able to be looked at.
